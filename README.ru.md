# Latent Code Memory

> **Компактные нейронные представления для reasoning по коду целого репозитория**

**Статус:** Исследование / ранняя стадия разработки  
**Категория:** AI / Machine Learning / Code Intelligence / Representation Learning  
**Фокус:** Латентные представления, информационные bottleneck'и, reasoning по коду, LLM

---

## Обзор

Современные языковые модели способны удивительно хорошо работать с исходным кодом, однако их возможности при работе с большими кодовыми базами ограничены количеством информации, которую необходимо передать через контекст модели.

Репозиторий может содержать десятки или сотни тысяч токенов:

```text
Репозиторий
├── исходный код
├── модули
├── классы
├── функции
├── зависимости
├── конфигурация
└── документация
```

Традиционный подход заключается в том, чтобы предоставить LLM необходимую информацию через большое контекстное окно, Retrieval-Augmented Generation (RAG) или многократный retrieval.

Этот проект исследует другой вопрос:

> **Можно ли преобразовать большую кодовую базу в компактное латентное представление, которое другая языковая модель сможет использовать для reasoning, не получая исходный код?**

Вместо передачи репозитория в виде текста encoder пытается сжать содержащуюся в нём информацию в фиксированное количество latent tokens.

Затем полученное представление передаётся отдельной языковой модели, которая пытается отвечать на вопросы о репозитории.

Концептуально:

```text
                    Традиционный подход

Репозиторий ──► Текст / Retrieval ──► LLM ──► Ответ


                    Latent-подход

Репозиторий
     │
     ▼
Code Encoder
     │
     ▼
Latent Bottleneck
     │
     │  фиксированное количество latent tokens
     ▼
Receiver LLM
     │
     ▼
Ответ
```

Цель проекта — не просто создать ещё одного code assistant.

Цель — исследовать **информационную ёмкость, поведение и ограничения latent communication для кода**.

# Исследовательский вопрос

Основной исследовательский вопрос:

> **Какое количество информации о репозитории можно сохранить в представлении фиксированного размера и насколько эффективно отдельная языковая модель сможет восстанавливать и использовать эту информацию для reasoning без доступа к исходному тексту?**

Из него следуют несколько дополнительных вопросов:

- Как изменяется качество при изменении количества latent tokens?
- Какие типы знаний о коде сохраняются при сжатии?
- Какая информация теряется первой?
- Можно ли сохранить семантическую информацию эффективнее, чем точные идентификаторы?
- Действительно ли receiver извлекает информацию из latent representation?
- Насколько на ответы receiver влияет его собственное pretrained knowledge?
- Как latent communication сравнивается с текстовым и retrieval-based подходами?
- Существует ли полезный trade-off между степенью сжатия и качеством reasoning?

# Мотивация

Большие кодовые базы создают фундаментальное противоречие.

Больше контекста предоставляет больше информации, однако обработка большого контекста увеличивает вычислительные затраты и создаёт дополнительные сложности.

Репозиторий может содержать:

```text
100 000+ текстовых токенов
```

при этом конкретному вопросу может требоваться лишь небольшая часть этой информации.

Поэтому традиционные системы пытаются выбрать наиболее релевантную информацию.

Этот проект задаёт другой вопрос:

```text
Большой репозиторий
       │
       ▼
обучаемое сжатие
       │
       ▼
маленькое латентное представление
       │
       ▼
reasoning-модель
```

Если такой подход окажется работоспособным, он может дать новый способ организации постоянной памяти для кода:

> Вместо многократного retrieval и передачи частей кодовой базы система могла бы поддерживать компактное обучаемое представление репозитория.

Однако здесь возникает фундаментальная проблема:

> **Сжатие не равно пониманию.**

Представление может быть чрезвычайно компактным, но при этом потерять именно ту информацию, которая необходима для надёжного reasoning.

Поэтому понимание этого trade-off не менее важно, чем достижение высокого коэффициента сжатия.

# Основная гипотеза

Начальная гипотеза:

> **Достаточно обученный encoder способен преобразовать код репозитория в компактное латентное представление, сохраняющее достаточное количество семантической и структурной информации для того, чтобы отдельная языковая модель могла выполнять полезный code reasoning без доступа к исходному тексту.**

Более конкретно, мы предполагаем, что разные типы информации обладают разной устойчивостью к сжатию.

Например:

```text
Информация репозитория

Семантика              ───────────────► потенциально устойчива
Архитектура            ───────────────► потенциально устойчива
Связи между компонентами ─────────────► потенциально устойчивы
Control flow           ───────────────► неопределённо
Точные идентификаторы  ───────────────► потенциально уязвимы
Точные значения        ───────────────► потенциально уязвимы
Редкие детали реализации ─────────────► потенциально уязвимы
```

Это **гипотеза, а не ожидаемый результат**.

Эксперименты могут показать, что гипотеза неверна.

Такой результат всё равно будет научно полезен.

# Latent Bottleneck

Центральным компонентом исследования является latent bottleneck фиксированного размера.

Вместо передачи:

```text
N текстовых токенов
```

encoder создаёт:

```text
K latent tokens
```

где:

```text
K << N
```

Например:

```text
Репозиторий
100 000 текстовых токенов
        │
        ▼
     Encoder
        │
        ▼
  128 latent tokens
        │
        ▼
   Receiver LLM
```

Важное свойство заключается в том, что `K` можно контролировать независимо от размера репозитория.

Это позволяет исследовать взаимосвязь:

```text
Сжатие
     ↕
Сохранение информации
     ↕
Качество reasoning
```

# Что такое Latent Token?

Обычный токен языковой модели соответствует некоторой части текста.

Например:

```text
def authenticate(user):
```

преобразуется tokenizer'ом в последовательность дискретных токенов.

Latent token принципиально отличается от этого.

Это обучаемый непрерывный вектор, используемый как часть внутреннего представления.

Он не обязан соответствовать:

```text
"def"
"authenticate"
"user"
```

Вместо этого информация может быть распределена между множеством latent vectors.

Концептуально:

```text
Код
 │
 ▼
Encoder
 │
 ▼
z₁  z₂  z₃  ...  zₖ
```

Эти векторы образуют communication channel между encoder и receiver.

Поэтому исследовательский вопрос заключается не в следующем:

> «Можно ли записать текст в меньшем количестве токенов?»

А в следующем:

> **«Может ли обучаемое латентное представление сохранять полезную для задачи информацию, не сохраняя исходное текстовое представление напрямую?»**

# Encoder и Receiver

Система концептуально состоит из двух отдельных компонентов.

## Encoder

Encoder получает исходный код и преобразует его в представление фиксированного размера.

```text
Код
 │
 ▼
Encoder
 │
 ▼
Latent representation
```

Задача encoder — извлечь из репозитория информацию, необходимую для дальнейшей работы.

## Receiver

Receiver получает latent representation и вопрос.

```text
Latent representation
          +
       Вопрос
          │
          ▼
     Receiver LLM
          │
          ▼
        Ответ
```

При inference receiver не получает исходный текст репозитория.

Это принципиально важно.

Так мы можем исследовать, содержит ли само латентное представление полезную информацию.

---

# Зачем нужны две модели?

Использование отдельных encoder и receiver создаёт явную задачу коммуникации.

Encoder должен научиться:

> Какую информацию необходимо передать?

Receiver должен научиться:

> Как интерпретировать переданное представление?

Концептуально это похоже на коммуникацию через канал с ограниченной пропускной способностью:

```text
Источник
  │
  ▼
Encoder
  │
  ▼
──── LATENT CHANNEL ────
  │
  ▼
Receiver
  │
  ▼
Предсказание
```

Количество latent tokens ограничивает ёмкость этого communication channel.

# Baselines

Latent-система не имеет смысла без сравнений.

Поэтому проект должен сравниваться с несколькими baseline-системами.

## Full-context baseline

Модели напрямую передаётся необходимый исходный код.

```text
Код ──► LLM
```

Это даёт ориентир для максимального количества доступной текстовой информации.

---

## Retrieval baseline

Используется обычная retrieval-система.

```text
Репозиторий
    │
    ▼
Retriever
    │
    ▼
Релевантные фрагменты
    │
    ▼
LLM
```

Это представляет практический подход к code intelligence.

---

## Embedding baseline

Используются обычные vector representations без обучаемого generative latent communication механизма.

Это помогает определить, действительно ли предлагаемая архитектура даёт что-то сверх стандартных embeddings.

---

## Latent baseline

Используется предлагаемая схема:

```text
Репозиторий
    │
    ▼
Encoder
    │
    ▼
Latent tokens
    │
    ▼
Receiver
```

Сравнение этих систем важнее абсолютного результата любой отдельной модели.

# Ожидаемые Failure Modes

Failure является полноценной частью исследования.

Возможные проблемы:

### Semantic collapse

Представление сохраняет только общие концепции.

```text
"аутентификация существует"
```

но теряет информацию о том, как именно она работает.

### Потеря идентификаторов

Система понимает назначение функции, но не может восстановить её точное имя.

### Потеря структуры

Модель знает, что делают отдельные модули, но теряет связи между ними.

### Потеря литералов

Исчезают точные значения, строки или элементы конфигурации.

### Receiver prior dominance

Receiver может генерировать правдоподобные ответы, опираясь на собственные pretrained priors, а не на информацию, реально переданную через latent representation.

### Hallucination

Receiver может выдавать убедительные, но не подтверждённые исходным кодом ответы.

### Saturation bottleneck

Увеличение latent capacity перестаёт улучшать производительность.

### Memorization

Система может хорошо работать на знакомых репозиториях, но плохо обобщаться на неизвестный код.

Эти failure modes должны исследоваться явно, а не скрываться.

---

# Особенно важная исследовательская проблема

Один из наиболее интересных вопросов заключается в том, действительно ли успешные ответы возникают благодаря latent representation.

Предположим, receiver отвечает:

> `Authentication is handled by validate_token().`

Есть как минимум два возможных объяснения.

### Случай A — настоящая latent-информация

Encoder действительно передал информацию, позволяющую определить `validate_token`.

### Случай B — pretrained prior

Receiver сгенерировал правдоподобный ответ, потому что такое имя или паттерн часто встречается в данных его обучения.

Это принципиально разные результаты.

Поэтому проект должен исследовать не только:

> **Правильно ли отвечает модель?**

но и:

> **Откуда взялась информация, необходимая для этого ответа?**

Это может привести к контролируемым probe-экспериментам, counterfactual experiments и анализу поведения receiver.

# Perspective информационного bottleneck

Проект можно рассматривать как задачу information bottleneck.

Мы имеем:

```text
              Большой источник информации
                       │
                       ▼
                  Репозиторий
                       │
                       ▼
                    Encoder
                       │
                       ▼
              ┌────────────────┐
              │ Latent channel │
              │    K tokens    │
              └────────────────┘
                       │
                       ▼
                   Receiver
                       │
                       ▼
                 Результат задачи
```

Канал обладает ограниченной ёмкостью.

Мы хотим понять:

> Какая информация сохраняется, когда communication channel становится всё более ограниченным?

Это делает проект более общим, чем просто code completion или repository search.

Код выступает экспериментальной областью, в которой мы изучаем latent communication.

# Потенциальные применения

Если подход окажется полезным, возможны следующие применения.

### Постоянная память репозитория

Репозиторий можно один раз закодировать и представить в виде компактной обучаемой памяти.

### Долгоживущие coding agents

Agent может поддерживать постоянное представление кодовой базы между различными взаимодействиями.

### Уменьшение контекста

Потенциально можно уменьшить необходимость многократно передавать большие фрагменты исходного кода.

### Коммуникация между моделями

Одна модель может кодировать информацию в latent representation, которую затем использует другая модель.

### Приватная или ограниченная коммуникация

Можно исследовать, возможно ли передавать полезную семантическую информацию без непосредственной передачи исходного текстового представления.

Это потенциальные применения, а не утверждения о продемонстрированных возможностях.

> «Наша модель превосходит все baseline'ы».

Успешный исследовательский проект может установить, например:

> Фиксированный latent bottleneck способен сохранять определённые типы информации о репозитории при значительном сжатии, однако точное восстановление идентификаторов резко ухудшается ниже определённой ёмкости.

Или:

> Latent representations значительно лучше сохраняют семантическую и архитектурную информацию, чем точную символьную информацию.

Или:

> Определённый training objective значительно улучшает сохранение информации при фиксированном latent budget.

Или даже:

> Latent communication не может конкурировать с retrieval для точного code reasoning, однако демонстрирует принципиальное различие между семантической и символьной информацией.

Хорошо подтверждённый отрицательный результат предпочтительнее неподтверждённого положительного вывода.

# Ограничения

У latent representations могут быть существенные ограничения.

Они могут:

- терять точную информацию;
- галлюцинировать;
- сильно зависеть от receiver-модели;
- плохо обобщаться между языками программирования;
- испытывать трудности с большими репозиториями;
- требовать дорогостоящего обучения;
- быть плохо интерпретируемыми;
- содержать информацию, которую невозможно напрямую декодировать;
- давать худшую практическую производительность по сравнению с сильными retrieval-системами.

Эти ограничения должны быть явно отражены в результатах.

# Долгосрочное направление

Долгосрочная цель проекта — исследовать более общий вопрос:

> **Могут ли нейронные модели передавать сложные структурированные знания через компактные обучаемые представления вместо непосредственной передачи исходного представления?**

Код является особенно удобной областью для исследования этого вопроса, поскольку содержит:

- точные символы;
- иерархическую структуру;
- семантические связи;
- зависимости на больших расстояниях;
- исполняемое поведение;
- информацию как высокого, так и низкого уровня.

Если проект окажется успешным, он потенциально может дать полезные выводы не только для code intelligence, но и для learned memory и коммуникации между нейронными моделями.

# Главный вопрос

В конечном счёте проект задаёт простой, но сложный вопрос:

> **Сколько информации о кодовой базе может знать языковая модель, если мы запрещаем ей видеть сам код и позволяем получать только небольшое обучаемое латентное представление?**

Цель заключается не просто в создании меньшего контекста.

Цель — понять **границы learned information compression и communication для reasoning по коду**.
